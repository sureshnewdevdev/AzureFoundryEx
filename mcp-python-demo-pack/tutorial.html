1. What MCP does

Model Context Protocol gives an AI host a standard way to discover capabilities from a server. The server does not need to contain an LLM.

User
→
MCP Host/Client
→
Python MCP Server
→
Data / APIs

Tools

Callable operations, usually selected by the model or host.

Resources

Read-only context identified by URIs.

Prompts

User-selected reusable message templates.

3. Minimal MCP demo

mcp dev examples/01_minimal_server.py

Call add, read greeting://Gopi, and render explain_mcp.

from mcp.server import MCPServer
mcp = MCPServer("Minimal Demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b

The function name becomes the tool name, the docstring becomes its description, and type hints become the input schema.

5. Three client approaches

In memory

python examples/02_in_memory_client.py

Best for learning and unit tests: no port or child process.

stdio

python examples/03_stdio_client.py

The client launches the server; common for local desktop hosts.

Streamable HTTP

python -m mcp_demo.http_server
# In a second terminal:
python examples/04_http_client.py

Endpoint: http://127.0.0.1:8000/mcp.

Do not print debugging text to stdout in a stdio server; stdout is the protocol channel.

6. Automated testing

pytest -q

Tests receive the server object directly and verify tools, structured results, resources, and prompts without a network server.

7. Production safety checklist

  • Validate every input and constrain schemas.
  • Require human approval for purchases, deletion, or messages.
  • Add authentication and authorization before remote exposure.
  • Keep credentials out of source and Git.
  • Use least privilege.
  • Annotations are hints, not access control.

9. Quick quiz

1. Which primitive is for a callable operation?

A tool.

2. Why use an in-memory client in tests?

It needs no subprocess, port, or network.

3. Is a tool annotation an authorization control?

No. Enforce security on the server.
